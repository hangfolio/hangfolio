# The site.yaml reference

`site.yaml`, at the top of your repository, says who you are and how your site is set up. Only five
fields are required: `name`, `tagline`, `role`, `affiliation` and `email`. Everything else is
optional, and a feature you don't configure simply doesn't appear.

```yaml
name: "Mara Quill"
tagline: "I measure tides with gauges that cost less than a bicycle."
role: "PhD student in Oceanography"
affiliation: { name: "Harbor University", url: "https://harbor.example" }
email: "mara@harbor.example"
location: "Lisbon"
avatar: "/images/mara.jpg"
cv: "/files/cv.pdf"
links:
  - "https://github.com/mara-quill"
  - "https://scholar.google.com/citations?user=XXXXXXXX"
  - { url: "https://orcid.org/0000-0002-1825-0097", label: "ORCID" }
```

Put text in straight double quotes, write paths from your site's root (`/files/cv.pdf` is the file
`public/files/cv.pdf`), and use spaces to indent. If something is wrong, the deploy stops and names
the line ([Troubleshooting](troubleshooting.md)).

## Links

Each link is either a bare address or a block:

```yaml
links:
  - "https://github.com/mara-quill"                       # label: GitHub
  - { url: "https://bsky.app/profile/mara.example", footer: false }
  - { url: "https://lab.example.org", label: "My lab", id: lab }
```

The label is worked out from the address when you leave it out: GitHub, Google Scholar, ORCID,
LinkedIn, X and Bluesky are recognised, and any other site shows its host name. Every link shows under
your name, on the contact page and in the footer, unless you set `hero`, `contact` or `footer` to
`false`. Projects and papers can reuse a link by its `id` (`{ label: "Code", profile: lab }`), which
defaults to the label in lower case, so renaming a label never breaks them.

## Availability and booking

`availability` adds a highlighted box to the home page and a status line to the contact page, and sets
the subject of the Email buttons. It hides itself after `until`.

```yaml
availability:
  headline: "Open to research internships · Summer 2027."
  detail: "Returning to the PhD afterwards."
  emailSubject: "Summer 2027 internship"
  until: 2027-06-01
```

`booking` adds a `/meet` page with your calendar, a menu item and a booking button:

```yaml
booking: { calcom: "mara-quill/30min" }               # embeds Cal.com's scheduler
booking: { link: "https://calendly.com/mara/30min" }  # or: just a link, no outside script
```

## Pages

`pages` turns pages off or changes their address and text. A page that is off has no menu item and
no sitemap entry, and two pages can't share an address ([E303](troubleshooting.md#e303)). The table
in the [field reference](#page-options) lists the pages; see [Customizing](customizing.md#pages) for
examples.

## The address

You never type your site's address. On GitHub, each build asks GitHub Pages where the site is served
and uses that, so it is right for `https://<username>.github.io/`, for a project site at
`https://<username>.github.io/<repository>/`, and for a custom domain, and it follows a repository
rename on the next build. Pull requests and other branches use the address the repository name
implies. A local preview uses `http://localhost:4321/`.

Set `url` only to pin the address, for example when you host the site somewhere other than GitHub
Pages. If it disagrees with what GitHub Pages reports, the build warns you and uses `url`.
