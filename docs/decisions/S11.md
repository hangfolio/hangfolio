# S11: YAML and front-matter positions as file:line:col

- Date: 2026-10-04
- Result: pass
- Decision: The validator parses each `.yaml` file, and each `.md`/`.mdx` front matter, itself with `yaml` (`parseDocument`, `prettyErrors: false`). It slices front matter with Astro's own regex and maps every offset through one `LineCounter` built over the whole file, plus the offset where the front matter starts. A zod issue path is turned into a node by walking map keys and list indices. A missing key is reported on its parent's line, or against the file alone when it is a top-level key. `keepSourceTokens` stays off because positions don't need it. The fallback (key path with no line) applies only to missing top-level keys and empty documents.

The spike was a throwaway project in `spikes/s11-yaml-positions` (Node 22.22.3, npm 10.9.8, `yaml` 2.9.1, `zod` 4.6.5, and `js-yaml` 4.3.2 for comparison, because Astro 7.3.5 parses front matter with js-yaml). A prototype (`locate.mjs`, quoted below) slices the front matter with the pattern from `@astrojs/internal-helpers/dist/frontmatter.js`, which `@astrojs/mdx` and the content layer also use. It parses with `yaml` and turns both YAML syntax errors and zod issue paths into file positions. A runner checked 15 sample files against line:col values counted by hand: the 10 required mistakes plus 5 edge cases (a BOM with a blank line and CRLF, a missing closing `---` with a later `---` in the body, an emoji before the error, a misindented list item, and an empty value). All 15 passed, both with and without `keepSourceTokens`, and the output was byte-identical in both modes. Six findings shape M2. (1) Line offsets: Astro's slice starts right after the opening `---`, not after its newline. When the file starts with `---`, yaml's own line numbers already match the file, but a slicer that starts on the next line is off by one. Blank lines before `---`, which Astro accepts, shift the count further. Adding the start offset to a file-wide `LineCounter` is right in every case. `prettyErrors` must be off, because the "at line N" it appends counts from the start of the slice. (2) Dates: js-yaml silently turns `2026-13-02` into 2027-01-02 and `2026-02-30` into 2026-03-02, while `yaml` keeps all dates as strings. So E204 must check the `yaml` parse, not Astro's collection data. (3) Cascades: yaml reports up to three errors on one misindented line, plus a `BAD_INDENT` on the line after a tab. Keeping one error per line and dropping that `BAD_INDENT` removes the noise, and errors on separate lines are still all reported. (4) zod 4 reports a failed union at the union's own path, so the runner follows the branch with the deepest issue paths. (5) yaml offsets count UTF-16 code units, so columns are converted to code points. (6) `keepSourceTokens` only adds `srcToken` (the source tokens); node ranges are identical without it.

For the three syntax errors tested (`a: x: y`, a duplicate key, a tab used for indentation), js-yaml throws and yaml reports an error, so nothing that passes this validator then fails in Astro on those. Two independent errors (`a: x: y` on lines 1 and 3) give two yaml errors, on lines 1 and 3, so a file with several mistakes is reported in one run. ## Notes for M2

- **Shorthands.** Lenient shorthands are normalised by a `z.preprocess` step. If an issue path then points inside the normalised object (say `links.0.label` for a bare URL), `locate()` stops at the deepest node that exists, which is the shorthand's own line. Decide "missing" from the zod issue instead of from `found`, so this case isn't reported as E203. With `safeParse(data, { reportInput: true })`, zod 4.6.5 gives a missing key `input: undefined` and an empty value `input: null` (checked).
- **Annotation ends.** For multi-line values, `end` can fall on column 1 of the next line. Clamp it to the end of the previous line before emitting `endLine`/`endColumn`.
- **Unclosed front matter.** When there is no closing `---`, Astro silently treats the whole file as body. E103 must therefore come from the validator, before Astro runs.

## Prototype (`locate.mjs`)

```js
import { LineCounter, parseDocument, isMap, isSeq, isScalar } from 'yaml';

// Astro's own front-matter pattern (YAML only), plus the d flag for match indices.
const FRONT_MATTER = /(?:^﻿?|^\s*\n)---([\s\S]*?\n)---/d;
const OPENER = /(?:^﻿?|^\s*\n)---/d;

export function load(file, text, { keepSourceTokens = false } = {}) {
  const lines = new LineCounter(); // over the whole file, not the slice
  lines.addNewLine(0);
  for (let i = text.indexOf('\n'); i !== -1; i = text.indexOf('\n', i + 1)) lines.addNewLine(i + 1);
  const pos = (offset) => { // UTF-16 offset -> code-point column, BOM not counted
    const { line } = lines.linePos(offset);
    const before = text.slice(lines.lineStarts[line - 1], offset).replace(/^﻿/, '');
    return { line, col: [...before].length + 1 };
  };
  let base = 0;
  let source = text;
  if (/\.mdx?$/.test(file)) {
    const fm = FRONT_MATTER.exec(text);
    if (!fm) {
      const open = OPENER.exec(text);
      const syntax = open ? [{ yamlCode: 'UNCLOSED_FRONT_MATTER', ...pos(open.indices[0][1] - 3) }] : [];
      return { doc: null, at: pos, syntax };
    }
    base = fm.indices[1][0];
    source = fm[1];
  }
  const doc = parseDocument(source, { keepSourceTokens, prettyErrors: false });
  const at = (offset) => pos(base + offset);
  const syntax = [];
  for (const e of doc.errors) {
    let offset = base + e.pos[0];
    const { line } = lines.linePos(offset);
    const prev = syntax.at(-1);
    if (syntax.some((s) => s.line === line)) continue;
    if (e.code === 'BAD_INDENT' && prev?.yamlCode === 'TAB_AS_INDENT' && prev.line === line - 1) continue;
    if (e.code !== 'TAB_AS_INDENT') { // move off the indentation to the first character
      const indent = / */y;
      indent.lastIndex = lines.lineStarts[line - 1];
      indent.exec(text);
      offset = Math.max(offset, indent.lastIndex);
    }
    syntax.push({ yamlCode: e.code, ...pos(offset), end: pos(Math.max(offset, base + e.pos[1])) });
  }
  return { doc, at, syntax };
}

export function locate({ doc, at }, path) {
  let node = doc?.contents;
  let start = node?.range?.[0];
  let matched = 0;
  for (const seg of path) {
    let next = null;
    if (isMap(node)) {
      const pair = node.items.find((p) => String(isScalar(p.key) ? p.key.value : p.key) === String(seg));
      if (pair) next = { node: pair.value, start: pair.key.range[0] };
    } else if (isSeq(node) && node.items[seg]) {
      next = { node: node.items[seg], start: node.items[seg].range[0] };
    }
    if (!next) break;
    ({ node, start } = next);
    matched++;
  }
  if (start === undefined) return null; // empty document: only the file can be reported
  return { ...at(start), end: at(node?.range?.[1] ?? start), found: matched === path.length, matched };
}
```

The runner (`run-samples.mjs`) maps each problem to a catalogue code. yaml's `TAB_AS_INDENT` becomes E102 and the unclosed opener becomes E103; every other yaml error becomes E101. On the zod side, `unrecognized_keys` becomes E201, a path that isn't found becomes E203, a refine tagged E204 becomes E204, and anything else becomes E202. For a failed union, the runner follows the branch whose issue paths go deepest.
