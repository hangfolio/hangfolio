# S2: What files does `build.format: 'preserve'` write for injected routes?

- Date: 2026-10-04
- Result: the planned approach fails, and the fallback passes. `injectRoute` alone writes `writing.html` and `writing/x.html`. A move after the build fixes this, and redirect endpoints write exact files.
- Decision: keep `build.format: 'preserve'` with `trailingSlash: 'ignore'`.
  - The theme's route table marks each route as file-shaped (`/projects` → `projects.html`) or directory-shaped (`/writing/`, `/writing/<slug>/`, `/projects/<id>/` → `…/index.html`).
  - In `astro:build:done` the theme moves each directory-shaped page from `<path>.html` to `<path>/index.html`. The `assets` map tells it which files each route wrote.
  - A same-named file from `public/` always wins.
  - Each `site.yaml` redirect is injected as its own endpoint route at exactly its `from` path.
  - Canonical, `og:url`, sitemap and JSON-LD URLs come from the route table through `absUrl()`, never from `Astro.url`.
  - With `urlFormat: directory`, nothing is moved.

**Question.** With every page injected by the theme, does `preserve` plus `trailingSlash: 'ignore'` write exactly `projects.html`, `writing/index.html`, `writing/x/index.html`, `about.html`, `about/index.html` and `404.html`, at base `/` and at base `/hangfolio`?

**What I tried.** I used the S1 scratch theme with astro 7.3.5. It injects:
- `/` from `index.astro`;
- `/projects` from `projects.astro`;
- `/writing` from an entrypoint named `writing/index.astro`;
- `/writing/[slug]` from `writing/[slug].astro`;
- `/404` from `404.astro`;
- for each redirect, an endpoint `redirect.ts` at `/about.html` and again at `/about/index.html`.

I built the packed install and the workspace install at `SITE_PAGES_URL=https://u.github.io` and `https://u.github.io/hangfolio`, in both `preserve` and `directory`, with the move turned off and then on. A checker compares the exact file list (ignoring `_astro/`) and flags any root-relative `href`, `src` or refresh `url` that escapes the base or starts with `//`. I also served the `/hangfolio` build with `hangfolio preview` and probed each URL form.

**Results.**
- **Every injected page is written in file form.** Without the move, Astro writes `writing.html` and `writing/x.html`. The entrypoint's file name makes no difference, and neither does a trailing slash in the pattern, because it is dropped. Astro 7.3.5 hard-codes this in `core/routing/create-manifest.js`: "For backwards compatibility, an injected route is never considered an index route" (`isIndex: false`). So PLAN's fallback of shipping entrypoints in both forms cannot work.
- **`directory` format** writes `X/index.html` for everything, including `projects/index.html`.
- **With the move**, all 8 builds (two layouts × two bases × two formats) have the exact expected file set and no link escapes the base. The base never changes the folder layout.
- **Redirects.** Endpoints write exactly `about.html` and `about/index.html`, with a refresh and canonical that include the base. The same entrypoint works at both patterns. A single root `[...redirect]` route also writes the right files, but in dev it logs a router warning for every unknown URL, so we use exact routes instead.
- **`Astro.url` is wrong for moved pages.** Inside a moved page, `Astro.url.pathname` is `/hangfolio/writing.html` at build time and `/writing` in dev. That is why canonical URLs must come from the route table.
- **Public files.** Astro 7.3.5 already skips a page whose output name exists in `public/` (`Skipping … because a file with the same name exists in the public folder`). It checks the name before the move, though. My first version of the move overwrote `public/writing/index.html`, and it also moved a public `writing.html` that Astro had skipped. The final version checks `public/` for both names. All four conflict cases now keep the public file.
- **Dev** answers `/writing`, `/writing/`, `/writing/x`, `/writing/x/` and `/projects.html` with 200.
- **Preview** of the moved build answers `/hangfolio/projects`, `/projects.html`, `/writing`, `/writing/`, `/writing/x`, `/writing/x/`, `/about.html`, `/about/` and `/about/index.html` with 200, and `/hangfolio/nope` with 404.

**Fallback.** This decision is the fallback: the move after the build plus exact endpoint routes. If a future Astro honours `isIndex` for injected routes, the move becomes a no-op; it skips anything already named `index.html`. The theme still owns the route table either way.
