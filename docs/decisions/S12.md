# S12: does a deep link preselect the template?

- Date: 2026-10-04
- Result: pass
- Decision: the README's "Create your site" button links to
  `https://github.com/new?template_owner=hangfolio&template_name=starter&owner=%40me&visibility=public`.

GitHub documents query parameters for `github.com/new` in "Creating a new repository"
(docs.github.com/en/repositories/creating-and-managing-repositories/creating-a-new-repository):
`template_owner` and `template_name` select the template (example from the docs:
`https://github.com/new?owner=avocado-corp&template_owner=avocado-corp&template_name=octo-repo`),
`owner` accepts a user or organization name or `@me` while signed in, `visibility` accepts `public` or `private`,
and `name` and `description` prefill those fields (spaces as `+` or `%20`). `include_all_branches` is not a supported
parameter, which suits us: the template has one branch. A signed-out visit was checked in a browser on 2026-10-04:
`https://github.com/new?template_owner=academicpages&template_name=academicpages.github.io` redirects to
`https://github.com/login?return_to=https%3A%2F%2Fgithub.com%2Fnew%3Ftemplate_owner%3Dacademicpages%26template_name%3Dacademicpages.github.io`,
so the template selection survives signing in. We set `owner=@me` so the copy lands in the visitor's own account rather than an
organization they happen to belong to, and `visibility=public` because GitHub Pages on a free plan needs a public repository. We do not
prefill `name`: the visitor chooses between `<username>.github.io` and a project name, and the README explains the difference.
