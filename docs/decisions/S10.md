# S10: what the Pages "Configure" suggestions commit, and how build.yml spots them

- Date: 2026-10-04
- Result: pass
- Decision: the `preflight` job of `build.yml` decides by content, not by file name. A file directly in `.github/workflows/` (`*.yml` or `*.yaml`) is a competing publisher when any of its `uses:` values starts with `actions/deploy-pages@` or `actions/upload-pages-artifact@`, unless `workflow_call` is its only trigger. A workflow that calls such a local reusable file also counts, and so does any file other than the caller that calls the engine's `deploy.yml`. `actions/jekyll-build-pages` is dropped from the SPEC 8.2 list, because it only builds. The file name and the `name:` line only choose the wording of the error. The rule is the script quoted below. It flagged all 158 real Pages workflows and 8 hand-made variants. It flagged nothing in the 8 negative repositories (18 workflow files), and it never flagged the copy's own `deploy.yml`, which sits beside every positive case. The planned fallback ("broaden the detection pattern") is not needed.

**Question.** Under *Settings → Pages → Build and deployment → Source: GitHub Actions*, GitHub suggests workflows with a **Configure** button. Which workflows can it suggest for an Astro repository, and what does each one commit: file name, `name:`, triggers and actions? Can `build.yml` reliably flag a committed suggestion as a second, competing deploy without flagging the copy's own `deploy.yml`?

The candidate rule ran against 176 test repositories, each a `.github/workflows` directory. The 158 real Pages workflows (9 current templates, 148 historical versions and the workflow from Astro's guide) each sit beside the copy's own `deploy.yml`. The other positive cases are 8 hand-made variants, one duplicate caller and one `gh-pages` branch publisher. The 8 negative repositories (18 workflow files) hold the copy's own caller, the real spike workflows and lookalikes. An independent checker that parses YAML with PyYAML 6.0.3 recomputed every verdict.

**Result: what Configure offers and commits.** There are nine Pages templates. Each card's title comes from its properties file. Configure opens the editor on `.github/workflows/<template file name>` (as 2022 write-ups show; not observed here), which the person can rename, and replaces `$default-branch` with the repository's default branch. That variable is the only one the Pages templates use.

| File | Card | `categories` | `name:` | Actions used (besides checkout, configure-pages, upload-pages-artifact, deploy-pages) |
|---|---|---|---|---|
| `astro.yml` | Astro | Pages, Astro | Deploy Astro site to Pages | setup-node@v4 (Node 20) |
| `static.yml` | Static HTML | Pages, HTML, JavaScript, CSS | Deploy static content to Pages | none (uploads the repository root, `path: '.'`) |
| `jekyll-gh-pages.yml` | GitHub Pages Jekyll | Pages, Jekyll | Deploy Jekyll with GitHub Pages dependencies preinstalled | jekyll-build-pages@v1 |
| `jekyll.yml` | Jekyll | Pages, Jekyll | Deploy Jekyll site to Pages | ruby/setup-ruby (SHA) |
| `nextjs.yml` | Next.js | Pages, Next | Deploy Next.js site to Pages | setup-node@v4, cache@v4 |
| `nuxtjs.yml` | NuxtJS | Pages, Nuxt | Deploy Nuxt site to Pages | setup-node@v4, cache@v4 |
| `gatsby.yml` | Gatsby | Pages, Gatsby | Deploy Gatsby site to Pages | setup-node@v4, cache@v4 |
| `hugo.yml` | Hugo | Pages, Hugo | Deploy Hugo site to Pages | none (installs Hugo with `wget`) |
| `mdbook.yml` | mdBook | Pages, mdBook | Deploy mdBook site to Pages | none (installs Rust with rustup, then mdBook with `cargo install`) |

All nine share the following:

- They are triggered by `push: branches: [$default-branch]` and `workflow_dispatch`.
- `permissions: contents: read, pages: write, id-token: write`.
- `concurrency: group: "pages", cancel-in-progress: false`.
- A deploy job with `environment: github-pages`.
- `actions/checkout@v4`, `actions/configure-pages@v5`, `actions/upload-pages-artifact@v3` and `actions/deploy-pages@v5`.

None of the properties files has `filePatterns`. Suggestions can therefore only come from matching `categories` against the repository's linguist languages and detected tech stacks. The README says matching templates "feature more prominently". `Astro` is in `tech_stacks.yml`, and GitHub already reports `language: Astro` (languages Astro, JavaScript and CSS) for the spike's minimal Astro site. So an Astro repository should be offered **Astro** (`astro.yml`) and **Static HTML** (`static.yml`, through JavaScript and CSS). Write-ups from the 2022 launch show **GitHub Pages Jekyll** (`jekyll-gh-pages.yml`) and Static HTML as the two cards for a repository with no detected framework. The other six are one click away under "browse all workflows". Which cards GitHub shows for the final `hangfolio/starter` is not certain, because its `package.json` lists only the theme. The rule covers all nine, so this does not matter.

**What a committed suggestion does.** By default the Configure commit goes straight to the default branch, so the same push starts both the suggestion and **Deploy site**. The two use different concurrency groups (`pages` and `pages-<repo>`), so neither waits for the other. GitHub Docs say Pages "does not associate a specific workflow to the GitHub Pages settings", so the last deployment wins. Two consequences follow:

- `static.yml` publishes the repository root as-is. A copy would then serve the root `index.html` "Almost there" page (SPEC 8.4) in place of the site.
- `astro.yml` builds with Node 20 and calls `astro build` directly. That skips `hangfolio check` and `hangfolio verify dist`, and Node 20 is below the theme's `engines.node`.

Astro's own guide adds a related risk. It tells people to create `.github/workflows/deploy.yml` (`name: Deploy to GitHub Pages`, `withastro/action@v6` then `actions/deploy-pages@v5`), which is the same path as our caller. Saved under another name, it is caught (case `P-astro-docs`). Pasted over our `deploy.yml`, it replaces the engine call, so `build.yml` never runs and cannot report anything. Only the README can prevent that.

**Result: the rule.** The `preflight` job checks out `.github/workflows` sparsely at `github.sha`. This needs `contents: read`; the caller's build job already grants it (SPEC 8.1), so `preflight` declares `contents: read` and `pages: read`. It then runs the script with `${{ github.workflow_ref }}` and the engine's `owner/repo`. Inside a called workflow, `github.workflow_ref` names the caller's file (evidence below), so the script knows which file is our own caller without assuming it is called `deploy.yml`.

The rule covers the following:

- **Competing publishers.** A file is one when any `uses:` value, at step or job level, starts with `actions/deploy-pages@` or `actions/upload-pages-artifact@`. Block, flow and quoted forms all count, any `@ref` (tag or SHA) counts, and the match ignores case. Comments and the text inside `run: |` and `run: >` blocks are ignored.
- **Reusable workflows.** A file whose only trigger is `workflow_call` is skipped, because it runs only when called. This keeps the engine repository's own `build.yml` and `deploy.yml` from flagging themselves. A non-caller file that calls such a local file through `uses: ./.github/workflows/<file>` is flagged instead.
- **Our own `deploy.yml`.** It is not exempt from the content check. It never names those actions, so it never matches, and a deploy job pasted into it is caught (case `P-var-extra-job-in-ours`).
- **Duplicate callers.** A file other than the caller that calls `<engine>/.github/workflows/deploy.yml@…` is a second copy of Deploy site, and it is treated as competing too.
- **Branch publishers.** `peaceiris/actions-gh-pages` and `JamesIves/github-pages-deploy-action` push a `gh-pages` branch, which does nothing once Source is GitHub Actions. They produce only a warning.
- **Scope.** Only files directly in `.github/workflows/` are scanned, because GitHub does not run files in its subfolders.

Any competing hit sets `state=competing` with every file listed. The SPEC 8.2/3.5 behaviour is unchanged: no upload, plus the **One step left** error. When the file name and `name:` both match one of the nine templates, the error names the card, for example: "`.github/workflows/astro.yml` is GitHub's suggested "Astro" workflow from Settings → Pages. It also publishes to GitHub Pages and will overwrite your site. Delete it; Deploy site already builds and publishes your site."

A plain case-insensitive search for the three action names, as SPEC 8.2 words it, produced 6 false positives on the negative cases, and a case-sensitive version missed the upper-case spelling. The rule produced no false positives and missed nothing (evidence below).

**Known limits.**

- A workflow that was disabled in the Actions tab is still flagged. The workflows API could exclude it, but that needs `actions: read`, which was not tested.
- A local composite action (`.github/actions/*`) that wraps `deploy-pages` is not followed.
- A third-party reusable workflow that deploys is not followed.
- A line inside a block scalar written without the `|`/`>` indicator could in theory match.
- The script was run only with macOS `awk` version 20200816. It uses POSIX awk only, but the runner uses a different `awk`.

The rule as tested, `detect.sh <workflows-dir> <caller workflow_ref> <engine owner/repo>`. It prints `kind<TAB>path<TAB>card`:

```bash
#!/usr/bin/env bash
set -euo pipefail
dir=${1:-.github/workflows}
ref=${2:-}
engine=$(printf '%s' "${3:-hangfolio/hangfolio}" | tr '[:upper:]' '[:lower:]')
self=${ref#*/}; self=${self#*/}; self=${self%%@*}          # owner/repo/.github/workflows/x.yml@refs/... -> .github/workflows/x.yml
self_base=${self##*/}

shopt -s nullglob nocaseglob
for f in "$dir"/*.yml "$dir"/*.yaml; do                   # GitHub runs only files directly in .github/workflows
  [ -f "$f" ] || continue
  base=${f##*/}
  LC_ALL=C awk -v base="$base" -v engine="$engine" '
    function indent(s) { match(s, /^ */); return RLENGTH }
    function trig(list,   n, a, i, t) {                    # list of trigger names from a flow value
      gsub(/[][{}"'"'"']/, "", list); n = split(list, a, ",")
      for (i = 1; i <= n; i++) { t = a[i]; sub(/:.*/, "", t); gsub(/ /, "", t); if (t != "") T[t] = 1 }
    }
    {
      if (NR == 1) sub(/^\357\273\277/, "")                 # BOM
      sub(/\r$/, "")                                         # CRLF
      line = $0
      if (blk >= 0) { if (line ~ /^ *$/ || indent(line) > blk) next; blk = -1 }   # inside a block scalar (run: |)
      if (line ~ /^ *#/) next
      sub(/[ \t]#.*$/, "", line)                             # trailing comment
      low = tolower(line)
      if (low ~ /:[ ]*[|>][-+0-9]*[ ]*$/) blk = indent(low)  # a block scalar starts on the next line
      if (low ~ /^name:/ && wfname == "") { wfname = low; sub(/^name:[ ]*/, "", wfname); gsub(/["'"'"']/, "", wfname) }
      # triggers
      if (low ~ /^["'"'"']?on["'"'"']?:/) {
        rest = low; sub(/^[^:]*:[ ]*/, "", rest)
        if (rest != "") trig(rest); else inon = 1
        next
      }
      if (inon) {
        if (low ~ /^ *$/) next
        if (indent(low) == 0) inon = 0
        else {
          if (onind == 0) onind = indent(low)
          if (indent(low) == onind) { t = low; sub(/^ *(- *)?/, "", t); sub(/[: ].*$/, "", t); T[t] = 1 }
        }
      }
      # every uses: value on the line (block, flow and quoted forms)
      s = low
      while (match(s, /(^|[ {,-])uses:[ ]*["'"'"']?[^ "'"'"',}]+/)) {
        v = substr(s, RSTART, RLENGTH); s = substr(s, RSTART + RLENGTH)
        sub(/^.*uses:[ ]*["'"'"']?/, "", v)
        if (v ~ /^actions\/(deploy-pages|upload-pages-artifact)@/) hit = 1
        if (index(v, engine "/.github/workflows/deploy.y") == 1 && v ~ /\.ya?ml@/) dup = 1
        if (v ~ /^(peaceiris\/actions-gh-pages|jamesives\/github-pages-deploy-action)@/) branch = 1
        if (v ~ /^\.\/\.github\/workflows\/[^\/]+$/) { sub(/^.*\//, "", v); calls = calls " " v }
      }
    }
    END {
      ntrig = 0; for (t in T) ntrig++
      callonly = (ntrig == 1 && ("workflow_call" in T))    # reusable only: runs only when another workflow calls it
      label = ""
      if (base == "astro.yml"           && wfname == "deploy astro site to pages") label = "Astro"
      if (base == "static.yml"          && wfname == "deploy static content to pages") label = "Static HTML"
      if (base == "jekyll-gh-pages.yml" && wfname == "deploy jekyll with github pages dependencies preinstalled") label = "GitHub Pages Jekyll"
      if (base == "jekyll.yml"          && wfname == "deploy jekyll site to pages") label = "Jekyll"
      if (base == "nextjs.yml"          && wfname == "deploy next.js site to pages") label = "Next.js"
      if (base == "nuxtjs.yml"          && wfname == "deploy nuxt site to pages") label = "NuxtJS"
      if (base == "gatsby.yml"          && wfname == "deploy gatsby site to pages") label = "Gatsby"
      if (base == "hugo.yml"            && wfname == "deploy hugo site to pages") label = "Hugo"
      if (base == "mdbook.yml"          && wfname == "deploy mdbook site to pages") label = "mdBook"
      # one record per file for the second pass: path base callonly hit dup branch label calls
      printf "%s\t%s\t%d\t%d\t%d\t%d\t%s\t%s\n", FILENAME, tolower(base), callonly, hit, dup, branch, label, calls
    }' blk=-1 "$f"
done | awk -F '\t' -v self="$(printf '%s' "$self_base" | tr '[:upper:]' '[:lower:]')" '
  { path[NR] = $1; base[NR] = $2; callonly[NR] = $3; hit[NR] = $4; dup[NR] = $5; branch[NR] = $6; label[NR] = $7; calls[NR] = $8
    if ($3 && $4) localdeployer[$2] = 1 }
  END {
    for (i = 1; i <= NR; i++) {
      if (base[i] == self) chain = 0
      else { chain = 0; n = split(calls[i], c, " "); for (j = 1; j <= n; j++) if (c[j] in localdeployer) chain = 1 }
      if ((hit[i] && !callonly[i]) || chain) printf "competing\t%s\t%s\n", path[i], label[i]
      if (dup[i] && base[i] != self)          printf "duplicate\t%s\t\n", path[i]
      if (branch[i] && !callonly[i])          printf "branch\t%s\t\n", path[i]
    }
  }'
```
