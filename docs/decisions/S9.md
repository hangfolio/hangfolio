# S9: Which BibTeX parser

- Date: 2026-10-04
- Result: pass
- Changed 2026-10-04: the denylist rule now covers only tracked files and pushed commits, so the theme depends on `@retorquere/bibtex-parser` 11.0.0 directly (pinned exactly, updated through Dependabot behind the torture-file tests). The vendoring step in finding 11 is dropped.
- Decision (original): Parse `publications.bib` with `@retorquere/bibtex-parser` 11.0.0, pinned exactly, behind a wrapper in `lib/bib.ts` of about 130 lines. The wrapper calls `parse(src, { sentenceCase: false, verbatimFields: LINK_FIELDS, unsupported })`. It recovers each entry's raw slice and its first and last lines from `entry.input`. It reports W301 on the broken entry's first line, folds all text to NFC, and escapes everything except a short list of allowed tags. The theme ships the parser pre-bundled as a single vendored ESM file (571 KB, built outside the repo), not as an npm dependency, because the npm package installs two data files that match the owner's denylist (AGENTS.md rule 2). If the owner limits that rule to committed files, the theme depends on the package directly instead. Fallback: citation-js for the fields, plus our own entry splitter (see below).

The spike was a throwaway project in `spikes/s9-bibtex` (Node 22.22.3, npm 10.9.8, esbuild 0.28.2). It compared four parsers on one torture file and 18 edge-case files (17 small files plus a CRLF copy of the torture file with a BOM): `@retorquere/bibtex-parser` 11.0.0, `@citation-js/plugin-bibtex` 0.9.0 with `@citation-js/core` 0.9.0, `bibliojson` 4.1.0 (the 2026 rename of `biblatex-csl-converter`) and `bibtex-parse` 2.1.0. The torture file (quoted at the end, all content invented) covers LaTeX accents in braced and unbraced forms, `@string` macros with `#` concatenation, a `crossref` child placed before its `@proceedings` parent, nested braces, `%` comments both between entries and inside one, `month` macros, a `(…)`-delimited entry, upper-case field names, and an entry with a missing comma in the middle. It ends with two Google Scholar entries pasted with no indentation, no blank line between them and no final newline. Each small edge-case file holds a good entry (lines 1–5), one problem entry starting on line 7, and a good entry after it. A runner (`compare.mjs`) put every parser through one adapter. It checked each entry's raw slice and its start and end lines against hand-counted values, 23 field values against the expected Unicode, and whether both good neighbours survived each edge case. Only retorquere met all three pass criteria. With the wrapper it returned 7/7 raw slices and 7/7 line ranges exactly, including on a CRLF copy with a BOM. It read 23/23 values correctly once its output was folded to NFC. It kept both neighbours in all 17 edge-case files, with W301 on line 7 wherever the entry was unreadable. citation-js converts LaTeX nearly as well, but any syntax error throws for the whole file (13 of the 17 edge-case files), and it gives no positions. bibliojson's `includeLocation`/`includeRawText` look like a fit, but its offsets and `raw_text` refer to a preprocessed copy of the input (accents already converted, whitespace collapsed), so 0/7 line ranges were right. A broken entry stays in its output with partial fields, and it mis-converts `Ji\v{r}\'{\i}` as "Jiř́ı"; it is also LGPL-3.0. bibtex-parse does no LaTeX conversion, turns `% TITLE = …` into a field named `% TITLE`, throws on the bad entry, and was last released in 2020.

## What `lib/bib.ts` must do around the parser (M5)

1. **Turn off sentence-casing.** By default, English titles are rewritten: `{}` gives "Bounded staleness for Edge caches", while `{sentenceCase: false}` gives "Bounded Staleness for Edge Caches".
2. **Drop half-parsed entries.** After a syntax error, the entry stays in `entries` with the fields read so far and `input: ""` (`broken2022comma still in entries: true fields: title input: ""`). Keep only entries whose `input` is non-empty.
3. **Find the slice, then cut it at the closing brace.** `entry.input` starts exactly at `@`, so `src.indexOf(entry.input, cursor)` (moving the cursor forward) gives the start offset. But `input` runs on through any `%` comment lines after the entry (`nunez2023accents input ends with: ",\n}\n\n% The child comes before its crossref parent, as BibTeX requires."`). So a 20-line scanner finds the real end. It uses the parser's own rules: braces nest, `\` escapes the next character, and `%` starts a comment only between fields.
4. **Report W301 on the entry's first line.** Each syntax error carries `input`, the text from the entry's `@` to the next `@`. Its offset gives the entry's first line; the message adds where the problem was found (`… at line 44, column 3`). After an error, the parser restarts at the next `@`, which can be an email address inside the broken entry. Skip an error that starts exactly where the previous one ended, unless its `@` begins a line. A stray `@` in free text between entries gets its own W301, as it would in BibTeX itself.
5. **Locate the other problems.** An unknown `@string` is reported without a position, and its name becomes the value; find its line by searching for `= name`. An unknown LaTeX command is reported without an entry and left as raw TeX; an `unsupported` callback receives the entry, so it can be reported against the entry's line (ignore those from `@preamble`). The parser does not flag duplicate or missing keys; the wrapper does.
6. **Fold the text to NFC.** All accents come out decomposed, with a combining mark (`"Caf\'e" -> "Café" NFC? false 43 61 66 65 301`), and `\'\i`/`\"\i` give a dotless ı plus the mark ("Naı̈ve"). `s.replace(/ı(?=[\u0300-\u036f])/g, 'i').normalize('NFC')` fixes all of them, and name matching needs it.
7. **Keep link fields verbatim.** al-folio's link fields are parsed as LaTeX by default, so `code = {https://example.org/~vale/code_v2#readme}` becomes `"https://example.org/ vale/code_v2#readme"` and `slides = {…/slides%20v2.pdf}` is cut at the `%`. Passing `verbatimFields: ['pdf', 'code', 'slides', 'poster', 'video', 'website', 'html', 'supp', 'arxiv', 'blog']` (added to the built-in `url`, `doi`, `eprint`, `file`) keeps every one byte for byte.
8. **Escape the output.** Values mix a few HTML tags (`<i>`, `<b>`, `<sup>`, `<sub>`, `<span class="nocase">`, a small-caps span, `<a href>`) with unescaped `<` and `&`, so they are not safe HTML. Escape everything, then restore only those tags; `<a>` is dropped, because links come from the `url`/`doi` fields. A literal `{<}` renders as "¡", as it does in LaTeX's OT1 encoding. `\url{…%…}` in `howpublished` is cut at the `%`. Both are rare.
9. **Small mappings.** Scholar's "and others" arrives as an author `{lastName: "others"}`; render it as "et al." `month = sep` becomes `"9"`, and `may # "~13--17"` becomes `"05 13–17"`; only the year is displayed. A child entry inherits `booktitle`, `editor`, `publisher` and `year` through `crossref`, but not `address`.
10. **Remove hidden fields from the raw text.** The same scanner splits a slice into fields at top-level commas and removes `abstract, file, keywords, annote, example`. Everything else stays byte for byte, and the trailing comma is fixed when the last field is removed. This was checked on six shapes: the torture entry, the starter's entry with `example` first, a Scholar entry whose last field is hidden, a one-line `(…)` entry, a hidden field after a `%` comment, and an entry with nothing hidden, which stays unchanged. The block shows `@string` names and `crossref` exactly as the user wrote them, so a copied entry that uses them won't compile on its own; the publications doc should say so (Scholar exports never use them).
11. **Vendor the parser or depend on it.** Only `dist/esm` is loaded at run time. `dist/data/unabbrev.json` (6.9 MB) and the declared dependencies `wink-nlp`, `wink-eng-lite-web-model`, `nearley` and `i` (about 5 MB with their own dependencies) are never imported. Two of these files match the denylist: `unabbrev.json` and the wink English model's JSON. The npm package names match nothing (`package-lock.json`: 0 matches). An esbuild bundle of `export { parse } from '@retorquere/bibtex-parser'` has no denylist matches. It gave output identical to the npm package on all 20 test files and shrinks the install from 34 packages to none. M5 adds a script that installs the exact version in a temp directory outside the repo, bundles it into `packages/theme/vendor/bibtex-parser.mjs`, and writes the licence notices for the 14 bundled packages next to it. Those are `@retorquere/bibtex-parser` and `unicode2latex` (ISC), `moo` (BSD-3-Clause) and 11 MIT packages. Updates then go through that script instead of Dependabot.
12. **Pin exactly and treat upgrades as risky.** The package has had two major releases in 2026 (10.0.0 on 05-16 and 11.0.0 on 09-09). The torture file and the edge cases become `packages/theme` unit tests and gate every upgrade.

## Fallback

If retorquere regresses or is abandoned, switch to citation-js (MIT, 7 small packages, 0 denylist matches) with our own splitter. The splitter is the end scanner from finding 3, extended to resynchronise on the next line that starts with `@`. Each slice is parsed separately with the file's `@string` definitions prepended, and crossref is resolved in our code. That costs about 100 more lines. Even then, citation-js leaves `\aa`, `\AA`, `\ldots`, `\dots` and `\S` as raw TeX, and its core depends on `sync-fetch-undici`, which spawns a child process for network fetches. bibliojson is not a fallback, because of its preprocessed offsets and its LGPL licence.
